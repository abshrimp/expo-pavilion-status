# expo-pavilion-status

大阪・関西万博2025の当日予約状況を記録したログをもとに、**ちょうど1年前の同じ日時**の
予約状況を再生して表示する非公式サイトです。

## 予約状況の表示はバックエンド不要（完全静的）

v1 はライブAPIをスクレイプする常駐サーバー（`server.js`）＋ `save.php` でデータを配信していましたが、
v2 の**予約状況表示は常駐バックエンドを持ちません**。過去ログを事前に「1日1ファイル」の静的JSONへ変換しておき、
ブラウザがその日のファイルを取得して「現在時刻−1年」の状態をクライアント側で復元します。
（後述の「当日予約ランキング」演出だけ、任意で軽量PHPを使います。）

各 `<日付>.json` の中身:

```jsonc
{
  "date": "2025-06-07",
  "base": { "HEH0": { "0900": 2, ... }, ... },          // 朝8:20時点のベースライン
  "ev":   [ ["14:01:19","HEH0","1700",0], ... ]          // 時刻順の変化イベント
}
```

復元は「`base` を複製 → `ev` のうち現在時刻(HH:MM:SS)以前のものを順に適用」するだけです
（[`src/services/expoService.js`](src/services/expoService.js) の `fetchExpoData`）。
状態 `s` は `0=空きあり / 1=残りわずか / 2=空きなし / その他=予約枠なし`。
当日予約と同様に、**開始時刻を過ぎた枠は表示しません**（リプレイ時刻以降の枠のみ表示）。

## 当日予約ランキング（任意のPHPバックエンド）

◯（空きあり）の枠をタップすると「予約されました」風モーダルが出ます。このモーダルに
**「本日このパビリオンを何番目に予約できたか」** を表示するため、
[`public/reserve.php`](public/reserve.php) を使います（無くてもモーダル自体は番号なしで動作）。
`public/` 配下なので **`npm run build` で `build/reserve.php` として自動的に同梱**されます。

- フロントは同一オリジンの `POST reserve.php`（`{ code, bid }`）を叩き、`{ rank, total, repeat }` を受け取って表示。
- `bid` は端末ごとにlocalStorageへ保存するブラウザID。
- **同一IP「または」同一ブラウザは、各パビリオンにつき実時刻の当日1回までしか加算しません**
  （2回目以降は初回の番号をそのまま返す）。日付は実時刻（JST）の当日でバケット。
- 保存先は `reserve.php` と同じ場所の `reservations/<YYYY-MM-DD>.json`（IPはハッシュ化）。`flock` で排他制御。

デプロイ: **`build/` の中身をアップロードするだけ**（`reserve.php` も同梱済み）。配信先で `reservations/`
ディレクトリへの書き込み権限が必要（無ければ `reserve.php` が自動作成）。呼び出し先は `REACT_APP_RESERVE_URL` で変更可。

> 補足: 「1日1回」はパビリオン単位です（別のパビリオンはそれぞれ1回ずつ加算）。全パビリオン通算で1日1回にしたい場合は
> `reserve.php` のキー設計を変えるだけで対応できます。

## セットアップ

### 1. 過去ログから静的ファイルを生成（初回・データ更新時のみ）

アプリ直下で:

```bash
node dev/build-history.mjs
# -> public/history/ に *.json（各日 + names.json + index.json）を生成
```

入力（すべて `dev/` 同梱）:

- `dev/data.csv` … `server.js` が出力した `log.txt`（予約状況の変化ログ）
- `dev/data.json` … 施設名マップ（コード→施設名。元 data2.json）
- （任意）リポジトリ直下の `server.js` … 手動の施設名辞書。あれば不足分の名称を補完（無くても可）

生成物は `public/history/` に出力されます（全133日で合計約50MB）。

### 2. 開発サーバー

```bash
npm install
npm start            # http://localhost:3000  （public/history も静的配信される）
```

`npm start`（CRA開発サーバー）は **PHPを実行しない**ため、そのままでは `/reserve.php` が 404 になります。
当日予約ランキングを開発中に試すには、別ターミナルでPHPを立ててください（`src/setupProxy.js` が
`/reserve.php` だけそのPHPサーバーへ転送します。本番ビルドには無関係）:

```bash
php -S 127.0.0.1:8000 -t public   # 別ターミナルで起動してから npm start
```

ランキングの動作確認だけなら、本番ビルドをPHPで配信するのが手軽です:

```bash
npm run build
php -S 127.0.0.1:8080 -t build    # http://127.0.0.1:8080 でアプリ＋reserve.phpが同一オリジンで動く
```

### 3. 本番ビルド & デプロイ

```bash
npm run build        # build/ に history/ ごとバンドルされる
# build/ の中身を静的ホスティング（expo.ebii.net など）にアップロードするだけ
```

## 設定

- `REACT_APP_YEARS_BACK`（既定 `1`）… 何年前を表示するか。
- サブパス配信時は `package.json` の `homepage` を設定してください（`history/` の取得パスに反映されます）。

## v1 からの主な変更点

- データ取得をライブAPIから静的ファイル＋クライアント復元へ置き換え（バックエンド廃止）。
- ヘッダー/タイトル/説明を「1年前の予約状況」に変更。
- 予約導線（予約モーダル・チケットID・予約画面リンク）は過去データでは無意味なため削除し、
  表は閲覧専用に。
- 表示する日時を「現在」ではなく「ちょうど1年前の同時刻」に変更。
